# Designing for AI Engineers: UI Patterns You Need to Know

Designing for AI engineers requires specific UI principles distinct from general design. Three guiding principles: condensed information welcomed (much like B2B data science and fintech) with strong hierarchy; parsed metadata most clear through tables, side drawers, tagging systems; follow Jakob's Law—users spend more time on other sites so established patterns from leaders like HuggingFace and OpenAI should be followed unless strong reason to deviate. GitHub Primer design system exemplifies developer-focused principles: not fully shipped until fast, additions dilute everything else, practicality beats purity, approachable better than simple, half measures bad as nothing, encourage flow, favor focus over features.

## Key Patterns & Concepts

- **Condensed Information**: Welcome dense data with strong visual hierarchy; reduce margins versus typical consumer UX
- **Parsed Metadata**: Extract metadata making searchable/filterable; key elements: tables, side drawers, tagging systems
- **Jakob's Law Application**: Follow established patterns from leaders when no strong deviation reason; users familiar with patterns elsewhere
- **Not Fully Shipped Until Fast**: Performance is non-negotiable; optimize speed as primary requirement
- **Additions Dilute**: Each added feature dilutes everything else; minimize feature addition
- **Practicality Beats Purity**: Choose practical solutions over ideologically pure approaches
- **Approachable > Simple**: Design for approachability not just simplicity; lower learning curve
- **Half Measures Problematic**: Commit fully to features; half-shipped features worse than nothing
- **Encourage Flow**: Maintain user momentum through experiences; avoid friction
- **Focus Over Features**: Prioritize focused capability over broad feature set
- **MVP-First Approach**: Release designs as MVPs initially then iterate live using external validation
- **Real External Validation**: Build from existing systems getting external feedback fast rather than perfecting internally

## Full Article

Head of Design at Modular AI, team going 0 to 1 on many AI products and workflows this year. Even with years designing for developers, personally ramped quickly on AI-specific topics building personas.

### Guiding UI Principles for AI Engineers

**1. Condensed information welcomed**: Much like B2B industries (data science, fintech), personas welcome dense data—as well as it's designed with strong hierarchy. Reduce those margins!

**2. Parsed metadata most clear**: Extracting out metadata making searchable/filterable/sortable important. Tables, side drawers, tagging systems—these main design system elements to refine.

**3. Remember Jakob's Law**: Users spend more time on other sites than yours. Strong leaders in AI like HuggingFace and OpenAI established patterns. If no strong reason deviating, go with it.

### GitHub Design System Principles

GitHub's Primer design system clearly custom to developer persona:

- **Not fully shipped until it's fast**: Performance non-negotiable
- **Anything added dilutes everything else**: Minimize addition
- **Practicality beats purity**: Choose practical over ideologically pure
- **Approachable better than simple**: Lower learning curve beats ultimate simplicity
- **Half measures bad as nothing at all**: Commit fully; don't half-ship
- **Encourage flow**: Maintain momentum and reduce friction
- **Favor focus over features**: Focused capability better than broad feature set
