# Dashboard Design Best Practices and Rules

Dashboard design requires clarity presenting complex information simply within 5 seconds. Most important rule: define dashboard purpose first. Operational dashboards present critical information quickly for time-sensitive tasks showing data deviations and current resources. Analytical dashboards provide at-a-glance information for analysis and decision-making less time-sensitive. Choose right data representation: scatter/bubble/network charts show relationships, line/column/bar charts enable comparison, pie/donut show composition, distribution charts reveal outliers. Follow clear naming conventions, consistent date formatting, truncated large values. Define layout prioritizing top-left attention, grid-based organization preventing cognitive overload. Use cards with consistent structure: name top-left, controls top-right, content below. Double margins using white space for clarity. Don't hide information relying on scrolling; prioritize above-fold content. Use 5-7 maximum widgets. Personalization beats customization ensuring users see relevant content. Data tables great for showing large item information sets. Design dashboards last after other views to leverage existing components.

## Key Patterns & Concepts

- **Define Purpose First**: Operational (time-sensitive quick alerts) vs Analytical (decision-making trends)
- **Data Representation**: Match chart type to data need—comparison, relationship, composition, distribution
- **Avoid Wrong Charts**: Skip gauges, 3D charts, overstyled visuals; low readability
- **Clear Conventions**: Consistent naming, date formatting, truncated values
- **Grid-Based Layout**: Invisible lines ensuring alignment and composition system
- **Prioritization**: Top-left gets natural attention; arrange by importance and dependencies
- **Card Structure**: Consistent internal layouts—title top-left, controls top-right, content remainder
- **White Space Critical**: Double margins; white space matters as much as typography
- **Above-Fold Content**: Summarize showing key info only; interactions as secondary not primary
- **Widget Limitation**: Maximum 5-7 widgets preventing overwhelming users
- **Personalization Over Customization**: System delivers role-based content before user customization
- **Data Tables**: Excellent for large item information sets; interactive and scalable
- **Design Last**: Dashboard is summary view; design after other pages ensuring component reusability
- **Interactive Data**: Ensure data tables and lists remain interactive with correct alignment
