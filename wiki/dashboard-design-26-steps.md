# Dashboard Design Process: 26 Steps Framework

Complete dashboard design process learned over 4-year journey as Product and Dashboard Designer involves five phases: pre-process, low-fidelity, work/design, assets & delivery, final & test. Pre-process phase: get inspiration asking client/team three example dashboards providing clarity both parties; learn personas creating 4-5 actual user personas helping identify issues; setup exact goals determining what track (signups, payment methods, etc.); setup project folder collecting moodboards from Dribbble, Behance, Pttrns, Pinterest saving to inspiration folder. Low-fidelity phase: whiteboard sitting team sketching ideas on whiteboard/paper/iPad discussing edge cases creating 2 design options; map screen info listing user inputs and stories; write all possible states addressing empty states error states; prepare diagram using Camunda Modeler for scalable technical diagramming. Work/design phase: moodboard describing visual ideas before pixels; first draft mixing screens getting feedback without pixel perfection; write copy setting tone crucial to user decisions; first intern test with 3-4 non-involved people testing prototype validating design decisions; maintain file etiquette keeping folders tidy max 8 layers; create UI elements using Sketch shapes with resizing properties enabling drag-and-drop; assets & delivery phase: specifications communicating decisions reducing developer difficulty; final prototype with all interactions ready; quicktime video screenshare going through prototype explaining everything; animate After Effects or Principle explaining movement; styleguide showing how elements react in different scenarios. Final & test phase: Inspectlet/Hotjar monitoring user sessions; Mixpanel validating goals and flows; Google Analytics tracking clicks understanding behavior.

## Key Patterns & Concepts

- **Gather Examples**: Ask for 3-4 inspirational pages/screenshots clarifying expectations
- **Personas Critical**: Create 4-5 actual user personas helping identify edge cases
- **Set Goals Early**: Define exact trackable metrics before design starts
- **Project Organization**: Source Files, Screens & Export, Inspiration & Resources folders
- **Whiteboard Sessions**: Team sketching ideas discussing edge cases creating options
- **Map Information**: List user inputs stories for each screen
- **Document States**: Address all possible states (empty, error, loaded, loading)
- **Diagram Flow**: Use Camunda Modeler for scalable technical diagramming
- **Moodboards**: Visualize design direction before pixel work
- **First Draft Fast**: Get feedback early without pixel perfection
- **Copy Matters**: Write clear microcopy tone setting crucial to decisions
- **User Testing Early**: Internal tests with 3-4 people not involved validating decisions
- **File Structure**: Max 8 layers per folder; maintain organization
- **UI Components**: Use Sketch resizing properties enabling team drag-and-drop
- **Specifications**: Document decisions and features clearly for developers
- **Prototypes Interactive**: 3-5 prototypes creating for different sessions all states prepared
- **Video Walkthrough**: Quicktime screenshare explaining prototype and design decisions
- **Animation Ready**: After Effects or Principle showing movement and interactions
- **Styleguide Complete**: Show element reactions in different states (error, disabled, loading)
- **Session Monitoring**: Inspectlet/HotJar capturing user sessions watching behavior
- **Validate Goals**: Mixpanel tracking flows and completions
- **Click Tracking**: Google Analytics tracking user clicks understanding behavior and patterns
