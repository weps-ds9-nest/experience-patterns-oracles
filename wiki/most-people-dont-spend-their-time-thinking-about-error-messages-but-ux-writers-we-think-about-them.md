# Most people don’t spend their time thinking about error messages. But UX writers? We think about them a lot.

Most people don’t spend their time thinking about error messages. But UX writers? We think about them a lot.

UX writers use plain, clear language for all their content. And error messages are no exception. In fact, error messages are usually the most in need of a UX writer’s magic.

An error message displaying technical jargon and incomprehensible lines of numbers.

Your error message needs to do two things:

1.   Tell the user what happened
2.   Tell the user how to resolve it

It’s that simple.

## 1. Tell the user what happened

There’s no reason not to tell a user what has happened. When they’re at the receiving end of the message don’t frighten or stress them out.

It’s important to remember not to blame the user. Even if they’ve clicked the wrong button, it’s probably because they thought it was the right one. The design and content should solve these usability problems. It’s not the user’s fault.

So make sure your message doesn’t direct blame, or better still, takes responsibility. Let’s look at an example.

Error message that reads: ‘Your email address hasn’t been entered’.

If you get this message, you’re concerned — why hasn’t it been entered? Who should enter it? That’s because this message is in passive voice. The active voice version is clearer:

This active message is also instructive. It tells the user what to do without assigning blame to them. This subtle change in language can make all the difference to a user’s understanding.

For some error messages it’s especially important to take responsibility. If there’s a system issue (such as a vaguely named ‘error 500’) you want to make sure the user doesn’t think it’s their fault.

Error message that reads: ‘Oops, you’ve broken it’.

This example doesn’t really tell them what’s happened. This might feel like brand personality, but it comes off as rude. It’s better to keep your user on your side if there’s a problem.

With system errors you can’t always have a message for every eventuality. But you can still take blame away from the user:

Error message that reads: ‘Sorry, something has gone wrong’.

## 2. Tell the user how to resolve it

You then need to make sure the user knows what to do next. The email example is good, because it does just that:

But with the system error, there might not be anything they can do except try again. So tell them that:

Error message that reads: ‘Sorry, something has gone wrong — please try again later’.

At least with this, the user knows it’s not their fault and they need to come back later.

Another example is if they’re confirming their password by entering it a second time:

Error message that reads: ‘That doesn’t match — please enter the same password’.

This tells them what’s wrong and what they need to do.

## A note on ‘personality’

There’s a big push to inject brand personality into every inch of writing. And having fun with words is no bad thing. But sometimes the user just needs to know something. You can have friendly messages that are still clear. But if you’re using bad puns for your error messages the user has no idea what’s going on.

> “Are your users inspired by you, or do they just want to do the thing?” — [Sarah Richards](https://contentdesign.london/)

With short and clear messages users can get on confidently.

UX writing in some ways is the opposite of marketing. It’s not writing that’s noticeable or inspires the user to relate to the brand or product. It’s writing that’s so quick and easy to understand you don’t even realise it’s there.
