# User retention is a major challenge in the digital space, with a significant percentage of users abandoning apps shortly after installation.

User retention is a major challenge in the digital space, with a significant percentage of users abandoning apps shortly after installation.

The sad truth is that **people largely abandon applications for reasons which are within our control**: **_Users leave apps because they do not perceive value from interacting with the software_** and because they not have a good experience interacting with it.

Imagine a **recipe search application****where users can search**, and filter, for recipes **based on criteria like time to prepare the recipe**, ratings or ingredients.

One day an **user searches for a recipe that doesn’t exist** and they encounter the following empty state.

**In this scenario users are left uncertain about whether there are genuinely no tasks that meet their criteria, if an error occurred**, or if the system is still processing the request. This uncertainty can lead to user frustration and wasted time as they may repeatedly refresh the query or adjust filter settings.

**To solve this issue a message within the content area at completion of the process** (e.g., “Sorry, no results were found for “cakke””) would be a simple yet **effective way to increase the**[**visibility of system status**](https://www.nngroup.com/articles/visibility-system-status/) and, therefore, user confidence in the results.

## What Is an Empty State?

Empty states are interface elements — **screens**, **containers** or panels — **that do not have any content to display about the product**.

This can happen **_when a user first time opens an application_**; **_when data has been deleted or is unavailable_**; **_when the user performs a search that returns no results_**; or **_when something goes wrong when the users are interacting with UI._**

Empty states must be designed carefully: **a well-designed empty state guides the user and provides a clear path forward**, while a poorly-designed empty state can be confusing and frustrating.

This article provides guidance for designing empty-state that turn the UX into an engaging and helpful experience, while simoultaneously improving usability, learnability, and discoverability.

## What purposes do empty state have?

Empty states have the potential to drive engagement, delight and retain users, especially during critical moments like initial app usage, content clearance, or when errors occur.

*   **Educate Users**: Empty states should **educate users about how to interact with the app effectively**. They should offer relevant contextual guidance and clarify the purpose of the section.
*   **Prompt Action**: **Empty states** should not only inform users but also **prompt and motivate** them **to initiate essential actions** by highlighting the benefits and providing a clear, straightforward path to get started.
*   **Delight Users**: In addition to education and motivation, delighting users is crucial for creating a positive and memorable experience. **Embracing creativity, injecting humor, and aligning with the brand’s unique personality can distinguish an app from its competitors, leaving a lasting** and enjoyable **impression on users.**

## What are the elements of an empty state

1.   **Image (Optional)**: An image or illustration relevant to the situation when the empty state occurs.
2.   **Title**: A short and straightforward explanation of the empty state that is easily understandable by all users. For example, “Your cart is empty,” or “No search results found”.
3.   **Body**: Clear and concise text that explains the next action to populate the empty space. It may also include why the space is empty and the benefits of taking the suggested step. For example, after the title “Your cart is empty,” the body text may say, “Shop to add items to your cart” to guide the user on what they can do next.
4.   **Primary Action (Button or Link)**: A call to action button or link that allows users to perform the primary action mentioned in the body copy of the empty state message. This action is typically the most important step for the user to take to resolve the empty state.
5.   **Secondary Call to Action (Optional)**: If there is a secondary action, such as a reference to a document for further reading or additional information, it can be included as a link below the primary action. This provides users with supplementary options or resources to address the empty state.

## Tips for Effective Empty State

### First Use

First Use Empty State have the **goal of helping users understand how the system works** and **emphasize the value of their activity.**

**Include a heading describing the current state** and what will be in the section once it is populated, **an explanation of how the feature works and motivation explaining why users should take action**, and a **CTA that points to the desired action**

*   Be contextual and don’t include content that is about other areas of the app.
*   **Don’t cover multiple options in one empty state.** If there are multiple things a user can do, pick the most important and keep the focus on that action. And don’t lead the user into a dead end. If there are useful next steps, include them.

## Errors

Errors Empty State have the **goal to help users understands the problem and suggest actions to take.**

Tips

*   **Error messages should pinpoint the problem precisely with a clear and concise message**. They should focus on helping users and avoid blaming them for mistakes. Instead of saying, “You made an error,” say, “We couldn’t process your request because…”
*   **Empty states should suggest actions users can take to fix it**. Include a direct link in your message copy or a primary action button to make the next action fast. Alternatively, guide them to the element they need to click.
*   **Provide clear contact information or a link to customer support for users who encounter persistent or complex errors.** Make it easy for them to get help when needed.
*   Adopt a **human, humble and friendly tone to ease frustration.** Incorporate icons or imagery to humanize the message.
*   While not suitable for all error situations, **tasteful humor can be incorporated into error messages to lighten the mood**. Humor should be clear, polite, and not come across as trying to cover up mistakes

## Conclusion

**When content does not yet exist for a screen use the empty state to provide cues**. Empty states should replace the element that would ordinarily show. For example, an empty state for a table should replace the table, the column headers and footer should not be present. This practice avoids having a screen reader read the entire table before getting to the message that there is no content in the table.

*   The **headline/title** of the empty state message **should start with a verb** and have a friendly voice and tone.
*   **Body text** should be short and informative, **telling the user what to do, how to do it and****how will it benefit the user.**
*   **Provide direct pathways (i.e. links) to getting started with key tasks related to populating the empty state.**
*   **Illustrations** are optional, but they **are a great way to add a touch of fun and visual interest while helping users understand what to do next.** These must be relevant to the action and mustn’t distract users.
