Buttons Placement and Order

**Buttons are critical elements that guide users through digital experiences.** Proper button placement can enhance user experience, while poor placement can cause frustration.

### OK button go first or last?

OK button go first or last?

**OK first** -> follows the natural reading order. This principle improves accuracy and prevents the user from scanning first through secondary actions. Also, it’s better for keyboard-controlled users who use the tab key for buttons.

 But… **OK last** -> improves the flow of a dialog by ending with its conclusion.

So which way is better?

Either option has good arguments in its favor, and as you can see below, operating systems handle button placement and sort order differently.

Windows and Apple approaches

So if you are, for instance, designing a MacOS application, it’s perfectly fine to follow Apple’s GUI standards.

**Otherwise, for general contexts, I tend to prefer using OK first, as I believe it has less consistency issues.**

In full-pages with forms, **use left alignment and order the buttons primary-to-secondary**, from left-to-right. This is where user’s attention is focused, following the “natural” reading order (for Western languages) resulting in increased form completion rates.*
