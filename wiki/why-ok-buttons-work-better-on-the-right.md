OK, this may be controversial. Or you may not have encountered a problem with the ‘OK’ buttons placement. When it comes to how to design the interaction regarding confirming and declining an action, where is the best placement for the confirmation of a request prompted to the user?

Is it to the left, or right?

Many do argue that the prime location of the ‘OK’ (or any other confirmation) button is to the right considering that this is the primary action that the user wants to take. But it is a heavily discussed area within UX regarding button placements.

#1 With the OK button on the left, the visual path the user has to go through is much longer.

#2 With the OK button on the right the visual path and confusing level is way lower.

## Left

By placing the ‘OK’ button on the left it supports the natural reading order in English and other languages that read from left-to-right. And makes for a natural flow from left to right. And there is also a practical use of placing the ‘OK’ button first, assuming most users need this button more often than ‘Cancel’, it’s a better user experience for keyboard users to place the ‘OK’ button first, considering it will take less keystrokes to navigate to.

## Right

But by listing the ‘OK’ button last greatly improves the flow, because the dialog box “ends” with the conclusion to choose ‘OK’ which in most cases would be the preferred option of choice for users. As seen in the examples above #2 has fewer visual fixations, which can provide the user with an easier and faster way to make a choice of which option to choose. If one assumes that the primary action for the dialog box will be ‘OK’, then it will be preferred to place the ‘OK’ button last, to avoid the user spending more time and getting confused on the action that should be taken. This option offers a faster visual flow.
